TCP vs UDP in Go: runnable echo server examples

By Boris Fain · Updated 9 September 2026

TCP delivers an ordered byte stream. UDP delivers separate datagrams without a delivery or ordering guarantee. These two Go echo servers make that difference visible. Both listen only on your own computer; no firewall changes are needed.

Choose the transport your application needs

PropertyTCPUDP
Data modelByte streamDatagrams
Message boundariesDefine your own framingDatagram boundaries preserved
DeliveryReliable ordered stream while the connection succeedsHandle loss, duplication and reordering yourself

UDP is not automatically faster for every workload. Retries and congestion handling can change the result. TCP delivery also does not prove that another application committed a business operation: use application acknowledgements when that matters.

Complete Go echo server

Save as echo.go. Run one mode per terminal. TCP messages end in a newline. UDP echoes each datagram.

package main

import (
	"bufio"
	"fmt"
	"log"
	"net"
	"os"
	"time"
)

func main() {
	if len(os.Args) != 2 {
		log.Fatal("usage: go run echo.go tcp|udp")
	}
	switch os.Args[1] {
	case "tcp":
		listener, err := net.Listen("tcp", "127.0.0.1:9000")
		if err != nil {
			log.Fatal(err)
		}
		defer listener.Close()
		fmt.Println("TCP listening on 127.0.0.1:9000")
		for {
			conn, err := listener.Accept()
			if err != nil {
				log.Print(err)
				continue
			}
			go handleTCP(conn)
		}
	case "udp":
		conn, err := net.ListenPacket("udp", "127.0.0.1:9001")
		if err != nil {
			log.Fatal(err)
		}
		defer conn.Close()
		fmt.Println("UDP listening on 127.0.0.1:9001")
		buffer := make([]byte, 2048)
		for {
			n, peer, err := conn.ReadFrom(buffer)
			if err != nil {
				log.Print(err)
				continue
			}
			if _, err := conn.WriteTo(buffer[:n], peer); err != nil {
				log.Print(err)
			}
		}
	default:
		log.Fatal("choose tcp or udp")
	}
}

func handleTCP(conn net.Conn) {
	defer conn.Close()
	if err := conn.SetDeadline(time.Now().Add(30 * time.Second)); err != nil {
		return
	}
	scanner := bufio.NewScanner(conn)
	for scanner.Scan() {
		if _, err := fmt.Fprintln(conn, scanner.Text()); err != nil {
			return
		}
	}
	if err := scanner.Err(); err != nil {
		log.Print(err)
	}
}

Run and test

go run echo.go tcp
# In a second terminal:
go run echo.go udp

With both servers running, save this Python 3 client as check.py and run python check.py.

import socket
with socket.create_connection(("127.0.0.1", 9000), timeout=3) as tcp:
    tcp.sendall(b"hello TCP\n")
    with tcp.makefile("rb") as stream:
        print(stream.readline().decode().strip())
with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as udp:
    udp.settimeout(3)
    udp.sendto(b"hello UDP", ("127.0.0.1", 9001))
    reply, peer = udp.recvfrom(2048)
    print(reply.decode())

Expected output:

hello TCP
hello UDP

Why does my TCP client wait?

The server waits for a newline. Sending hello without a newline does not finish a message. One write may arrive in several reads; multiple writes can arrive together. Use delimiters, length prefixes, or another explicit framing rule.

Understand the limits

The TCP deadline is 30 seconds for the whole connection, not a sliding idle timeout. Scanner limits line size by default. This demo starts a goroutine per connection without a connection cap. UDP packets larger than the 2,048-byte buffer can be truncated. Production systems need explicit size and connection limits, validation, authentication, and transport protection. Keep these examples on loopback.

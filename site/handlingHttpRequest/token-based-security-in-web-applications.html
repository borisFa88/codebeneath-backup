Token-Based Authentication in Web Applications

Written by

Boris Fain

in

HTTP Requests

very web application requires security, and one of the most effective methods to achieve it is through the use of tokens. However unlike traditional frameworks, which often operate as “black boxes” where developers cannot easily to see the internal mechanisms, my own implementing token-based security with code provides transparency and deeper understanding of how the system works. I recommend you to use my original code and just regenerate TokenGenerator.generate() method https://github.com/borisFa88/HttpTokenServer. I suppose it seemed unusual that I combined Java with Kotlin. But I choose Kotlin because Singletone is build into the language , in Java I would needed to implement it manually using static initialization or by double-check locking or relying any framework.

I recall when my team studied Microsoft COM technologies in the late 1990s. At first, the complexity was overwhelming, but once our team lead explained the concepts in simple terms, everything became clear. Similarly, token-based security can be explained with a straightforward analogy.

Only limited number individuals know the correct key for a house. Nodoby likes to see unknown or obscure people inside their home. The same way of thinking applies to networks. In the old standard approach there was user namer and password you had to enter it each time. But what if you need to access to different URL repeatedly? Each time you send you request with parameters and you also should to send token.

curl -POST ‘192.168.1.226:8000/login’ -H ‘Content-Type: application/json’ -d ‘{“username”: “admin”, password” : “secret” }’

or

wget -qO- –method=POST –header=’Content-Type: application/json’ –body-data='{“username”: “admin”, “password”: “secret”}’ http://192.168.1.226:8000/login

-qO is optional

if you don’t want to see Connecting to 192.168.1.226:8000… connected.

You response will be like {“token”:”50570d92-1851-4308-8076-55ce022d0b04″} each time you will see different token . And now you should to send it each time

curl -POST 192.168.1.226:8000/protected -H ‘Authorization: Bearer-50570d92-1851-4308-8076-55ce022d0b04‘

var random = new SecureRandom();            var bytes = new byte[32]; // 256-bit token

Java WebSocket Server Example With Jakarta WebSocket

Written by

Boris Fain

in

Sockets and File Transfer

WebSocket is a communication protocol that enables full-duplex, real-time communication between a client (usually a browser) and a server over a single TCP connection.

Unlike traditional HTTP, where the client must repeatedly request updates (polling), WebSocket keeps the connection open — allowing both the client and server to send data at any time.

Why Do We Need WebSocket?

Traditional HTTP works like this:

  1. Client sends request
  2. Server responds
  3. Connection closes

If you need real-time updates (chat, stock prices, live notifications), you must:

  • Poll the server repeatedly
  • Or use long polling (inefficient and heavy)

WebSocket solves this by creating a persistent connection.

Web socket is is like a TCP/UDP socket on one side and is running over the web and has all properties similar to HTTP on the other. See an example. 



package org.example;

import jakarta.websocket.OnClose;
import jakarta.websocket.OnError;
import jakarta.websocket.OnMessage;
import jakarta.websocket.OnOpen;
import jakarta.websocket.Session;
import jakarta.websocket.server.ServerEndpoint;

@ServerEndpoint("/ws")
public class ChatEndpoint {

    @OnOpen
    public void onOpen(Session session) {
        System.out.println("Client connected: " + session.getId());
    }

    @OnMessage
    public void onMessage(String message, Session session) {
        System.out.println("Received: " + message);
        session.getAsyncRemote().sendText("Echo: " + message);
    }

    @OnClose
    public void onClose(Session session) {
        System.out.println("Client disconnected: " + session.getId());
    }

    @OnError
    public void onError(Session session, Throwable t) {
        t.printStackTrace();
    }
}

The first step is handshake session onOpen annotation , where can inialize you data and check it for validation.

@onClose annotation is useful to close any resource had been allocated before.

@onMessage is method allows you to implement the logic between server and you web client . However you don’t read byte fromsocket you are using session object which is high level abstraction.

@onError is according the own name is useful to handle errors .

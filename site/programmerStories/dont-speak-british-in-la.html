Consistent Coding Style: The No Mixed Principle

Written by

Boris Fain

in

Programming Stories

If your code looks like a salad of styles, you don’t need a framework — you need therapy.
Yeah, I said it. pp
And before you get offended — read till the end, because you might actually thank me later.
Every day I see developers mixing everything:
🇬🇧 “colour” + 🇺🇸 “color”
UTF-8 + UTF-16
Tabs + spaces
Logic from Java, syntax from Python, indentation from Mars.

And then they wonder why the project breaks like glass under pressure.
It’s not bad luck. It’s mental laziness disguised as flexibility.

A few years ago, I came up with something that fixed this mess forever.
I call it the “No Mixed Principle” — or the U&S Pattern.

It started with something funny:
My son corrected me for writing “color” instead of “colour.”
He speaks American English.
I used British.
And that day I realized — mixing versions isn’t creativity… it’s confusion wearing a smile.

Now, let’s talk code.
I once saw this masterpiece in a “production” repo (yes, production

🤦‍♂️):
𝐟𝐮𝐧𝐜𝐭𝐢𝐨𝐧 𝐨𝐩𝐞𝐧𝐅𝐢𝐥𝐞(𝐒𝐭𝐫𝐢𝐧𝐠 𝐟𝐢𝐥𝐞𝐏𝐚𝐭𝐡) {
𝐅𝐢𝐥𝐞𝐈𝐧𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦 𝐢𝐧𝐩𝐮𝐭 = 𝐧𝐞𝐰 𝐅𝐢𝐥𝐞𝐈𝐧𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦(𝐟𝐢𝐥𝐞𝐏𝐚𝐭𝐡);
𝐢𝐧𝐩𝐮𝐭.𝐰𝐫𝐢𝐭𝐞(𝐲𝐨𝐮 𝐭𝐞𝐱𝐭);
}

𝐟𝐮𝐧𝐜𝐭𝐢𝐨𝐧 𝐜𝐥𝐨𝐬𝐞𝐅𝐢𝐥𝐞(𝐒𝐭𝐫𝐢𝐧𝐠 𝐟𝐢𝐥𝐞𝐏𝐚𝐭𝐡) {
𝐅𝐢𝐥𝐞𝐎𝐮𝐭𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦 𝐢𝐧𝐩𝐮𝐭 = 𝐧𝐞𝐰 𝐅𝐢𝐥𝐞𝐎𝐮𝐭𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦(𝐟𝐢𝐥𝐞𝐏𝐚𝐭𝐡);
𝐢𝐧𝐩𝐮𝐭.𝐰𝐫𝐢𝐭𝐞(𝐲𝐨𝐮 𝐭𝐞𝐱𝐭);
}

This person thought programming was easy.
And that “there’s nothing to learn.”

Then, the bugs came.
And they still didn’t understand why.

Here’s the version I fixed — with the No Mixed Principle in play:

𝐭𝐫𝐲 (𝐎𝐮𝐭𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦 𝐨𝐬 = 𝐧𝐞𝐰 𝐅𝐢𝐥𝐞𝐎𝐮𝐭𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦(“𝐮𝐭𝐟𝐅𝐢𝐥𝐞.𝐭𝐱𝐭”, 𝐚𝐩𝐩𝐞𝐧𝐝);
𝐎𝐮𝐭𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦𝐖𝐫𝐢𝐭𝐞𝐫 𝐰𝐫𝐢𝐭𝐞𝐫 = 𝐧𝐞𝐰 𝐎𝐮𝐭𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦𝐖𝐫𝐢𝐭𝐞𝐫(𝐨𝐬, 𝐒𝐭𝐚𝐧𝐝𝐚𝐫𝐝𝐂𝐡𝐚𝐫𝐬𝐞𝐭𝐬.𝐔𝐓𝐅_16𝐋𝐄)) {

𝐰𝐫𝐢𝐭𝐞𝐫.𝐰𝐫𝐢𝐭𝐞(𝐝𝐚𝐭𝐚 + 𝐟𝐨𝐫𝐦𝐚𝐭𝐭𝐞𝐝);
𝐰𝐫𝐢𝐭𝐞𝐫.𝐟𝐥𝐮𝐬𝐡();
} 𝐜𝐚𝐭𝐜𝐡 (𝐈𝐎𝐄𝐱𝐜𝐞𝐩𝐭𝐢𝐨𝐧 𝐞) {
𝐞.𝐩𝐫𝐢𝐧𝐭𝐒𝐭𝐚𝐜𝐤𝐓𝐫𝐚𝐜𝐞();
}

𝐭𝐫𝐲 (𝐁𝐮𝐟𝐟𝐞𝐫𝐞𝐝𝐑𝐞𝐚𝐝𝐞𝐫 𝐛𝐫 = 𝐧𝐞𝐰 𝐁𝐮𝐟𝐟𝐞𝐫𝐞𝐝𝐑𝐞𝐚𝐝𝐞𝐫(
𝐧𝐞𝐰 𝐈𝐧𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦𝐑𝐞𝐚𝐝𝐞𝐫(𝐧𝐞𝐰 𝐅𝐢𝐥𝐞𝐈𝐧𝐩𝐮𝐭𝐒𝐭𝐫𝐞𝐚𝐦(“𝐮𝐭𝐟𝐅𝐢𝐥𝐞.𝐭𝐱𝐭”), 𝐒𝐭𝐚𝐧𝐝𝐚𝐫𝐝𝐂𝐡𝐚𝐫𝐬𝐞𝐭𝐬.𝐔𝐓𝐅_16𝐁𝐄))) {

𝐒𝐭𝐫𝐢𝐧𝐠 𝐥𝐢𝐧𝐞;
𝐰𝐡𝐢𝐥𝐞 ((𝐥𝐢𝐧𝐞 = 𝐛𝐫.𝐫𝐞𝐚𝐝𝐋𝐢𝐧𝐞()) != 𝐧𝐮𝐥𝐥) {
𝐒𝐲𝐬𝐭𝐞𝐦.𝐨𝐮𝐭.𝐩𝐫𝐢𝐧𝐭𝐥𝐧(𝐥𝐢𝐧𝐞);
}

} 𝐜𝐚𝐭𝐜𝐡 (𝐈𝐎𝐄𝐱𝐜𝐞𝐩𝐭𝐢𝐨𝐧 𝐞) {
𝐞.𝐩𝐫𝐢𝐧𝐭𝐒𝐭𝐚𝐜𝐤𝐓𝐫𝐚𝐜𝐞();
}

They wrote in UTF-16LE and read in UTF-16BE.
Classic “I know what I’m doing” energy — until everything breaks.

It’s like driving up a mountain in 5th gear and thinking you’re smart…
Then wondering why your brakes melted halfway down.

The truth:
Most developers don’t need a new language.
They need discipline.
Pick one logic, one format, one pattern — and master it.

That’s what separates coders from craftsmen.
